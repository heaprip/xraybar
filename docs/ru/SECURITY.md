# Безопасность и доверие

[English](../SECURITY.md) · **Русский**

XrayBar запрашивает пароль администратора и стоит на пути всего вашего трафика. Вам не
должно быть нужно доверять автору, чтобы им пользоваться. Этот документ описывает, что
делает приложение, от чего оно может и не может защитить и как проверить это самостоятельно.

## Модель доверия в одном абзаце

Не доверяйте бинарникам, происхождение которых нельзя проследить: собирайте из исходников
(`scripts/make-app.sh`, только Command Line Tools) или берите релиз, который CI собирает из
коммита с тегом и аттестует (`gh attestation verify XrayBar-x.y.z.pkg -R heaprip/xraybar`
доказывает, какой workflow и какой коммит создали файл; что код безопасен, доказывает только
его чтение). Не верьте автору на слово насчёт исходников: они достаточно малы, чтобы их
прочитать, а `scripts/audit.sh` и `docs/ru/AUDIT.md` позволяют проверить их вам самим или
ИИ-модели, которую запускаете вы. Не доверяйте загрузкам: Xray-core и файлы `.dat`
проверяются по контрольным суммам из upstream. Самому Xray-core доверие оказывается как
upstream-проекту XTLS; XrayBar его не изменяет.

## Что делает приложение

| Область | Поведение | Где |
|---|---|---|
| Root | Без помощника: запрос пароля при каждом подключении запускает `xraybar-session.sh`. С помощником (по желанию, *Подключаться по Touch ID…*): LaunchDaemon, принадлежащий root, просит macOS авторизовать подключение (Touch ID или пароль, системное окно; один раз за запуск приложения, подтверждение хранится только в собственной авторизации XrayBar и недоступно другим правам и процессам) и запускает свою root-копию того же скрипта | `xraybar-session.sh`, `xraybar-install.sh`, `Sources/XrayBarHelper/main.swift` |
| От root | копирует конфиг в `/var/run/xraybar` и заменяет в нём секцию логов (только stdout), запускает xray (только версию, принадлежащую root, см. ниже), меняет DNS (и переносит эту настройку на новый сетевой сервис при смене сети), ждёт событий (`XrayBarHelper --watch` только наблюдает: процессы, стоп-файл, сеть), останавливает xray, восстанавливает DNS; `--restore` убирает следы погибшей сессии | тот же скрипт |
| Версии Xray | скачанный xray или xray из v2rayN сначала лежит в папке пользователя, затем root копирует его (один запрос пароля, `xraybar-install.sh --xray`) в `/Library/Application Support/XrayBar/xray/<версия>/xray`, принадлежащий root, и сверяет с SHA-256, который посчитало приложение. Любой другой xray сессия отклоняет | `xraybar-install.sh`, `6-Actions.swift` |
| Сеть (приложение) | только по запросу: загрузка Xray (версия, проверенная с XrayBar, сверяется с SHA-256, зафиксированным в исходниках, остальные — с `.dgst` своего релиза), список релизов Xray (api.github.com), данные маршрутизации (`.dat`, сверка с опубликованным SHA-256). Плюс один запрос к `cp.cloudflare.com/generate_204` через туннель после подключения с версией Xray, которая ещё не пропускала трафик. Эфемерная сессия без cookies и кэша | `7-Assets.swift` |
| Запись файлов | `~/Library/Application Support/XrayBar/` (библиотека, сгенерированный конфиг, стоп-файл, `core/` с файлами `.dat`, `download/`, пока загрузка ждёт установки); `/Library/Application Support/XrayBar/xray/` (root: установленные версии Xray; остаются при удалении помощника); `/var/run/xraybar/` (root: копия конфига на время подключения, pid; `/var/db/xraybar/dns.saved` переживает перезагрузку; лог читают только администраторы; в нём только ошибки, пока не включён «Подробный лог») | `2-Store.swift`, скрипт |
| Чтение файлов | перечисленное выше; по желанию база v2rayN для разового импорта (только чтение); буфер обмена — только по команде *Импорт ссылки или QR-кода из буфера обмена* (QR распознаётся на устройстве через Vision; приложение никогда не снимает экран) | `3-Import.swift`, `6-Actions.swift` |
| Процессы | запрос пароля (`NSAppleScript`), `xray run -test` для проверки конфига; `ditto` для распаковки и `xray version` после загрузки; `route -n get` перед подключением (не активен ли другой VPN) | `5-Session.swift`, `7-Assets.swift` |
| Секреты | VLESS id каждого сервера (его учётные данные) хранится в одной записи связки ключей входа, «XrayBar server credentials»; остальное в `library.json` (права 600). Если связка ключей недоступна на чтение или запись, id остаются в `library.json`. Во время подключения они есть в сгенерированном конфиге (права 600), пока у root-сессии не появится своя копия | `2-Store.swift` |

Больше ничего: ни телеметрии, ни отчётов о сбоях, ни проверки обновлений, ни аналитики. Ссылка
в *О программе XrayBar* открывается в браузере, только если по ней нажать. Приложение пишет смену
состояния и тексты сообщений в системный лог (подсистема `io.github.heaprip.xraybar`); имена
серверов, адреса и подробности ошибок помечены там как приватные.

## Модель угроз

Защищает от:
- того, что приложение делает не то, что написано в исходниках (собирайте сами);
- скрытой сетевой активности приложения (сетевой ввод-вывод разрешён в одном месте, его легко найти grep);
- остаточного состояния: осиротевших root-процессов, оставшихся маршрутов, DNS, который
  продолжает указывать в туннель, в том числе после потери питания или гибели root-скрипта
  (при следующем запуске предлагается «Восстановить сетевые настройки»);
- запуска под root бинаря из вашей учётной записи: сессия запускает только xray, который root
  установил в свой каталог, поэтому подмена файла в ваших папках ничего не меняет в том, что
  работает под root. Установка версии спрашивает пароль;
- запуска под root конфига, который пишет произвольные файлы: скрипт работает с собственной
  копией конфига, принадлежащей root, и сам записывает в неё секцию логов (plutil заново
  сериализует весь файл, так что экранированные или повторяющиеся ключи не протащат путь к логу).

Не защищает от (известные ограничения):
- **Вредоноса, уже запущенного под вашим пользователем.** Без помощника он может подменить
  скрипт сессии до того, как вы введёте пароль. С установленным помощником root-логика
  (помощник, скрипт и xray) принадлежит root и не меняется без прав администратора. Конфиг и
  данные маршрутизации (`.dat`) по-прежнему приходят из вашей учётной записи: секцию логов root
  переписывает, но серверы и маршруты считаются вашим выбором, так что такой вредонос может
  направить трафик в другое место. Он также может сам вызвать окно авторизации. v2rayN
  запускает ядра из каталогов, доступных пользователю, и передаёт пароль sudo через stdin.
- Скомпрометированного релиза Xray-core в upstream. Зафиксированный хеш доказывает, что вы
  получили ровно тот релиз, который проверялся, но не то, что он безопасен. Xray можно
  собрать из исходников с помощью Go и сравнить. Данные маршрутизации сверяются только с
  контрольной суммой из того же источника.
- Анализа трафика и всего, что выходит за рамки свойств безопасности самого Xray.
- Ошибок, которые ещё никто не заметил: код написан с помощью ИИ-агента, и независимый
  специалист по macOS его пока не проверял (README, «Как это сделано»).

## О бандле приложения

`scripts/make-app.sh` подписывает бандл ad-hoc. Команда `codesign --verify --strict XrayBar.app`
покажет, изменилось ли в нём что-нибудь после сборки, включая root-скрипт. Ad-hoc подпись не
содержит личности: тот, кто может изменить бандл, может и переподписать его. Поэтому она ловит
случайности и наивную подмену, но не целенаправленную локальную атаку. Developer ID и
нотаризации нет (D48): macOS просит разрешить первое открытие, а запись в связке ключей
спрашивает доступ ещё раз после каждого обновления, потому что для неё обновление с ad-hoc
подписью — другое приложение. Hardened runtime в бандле пока не включён, поэтому процесс,
запущенный под вами, может загрузить код в XrayBar; это даёт ему авторизацию XrayBar на
текущий запуск (подключение без нового Touch ID), но не больше: root по-прежнему запускает
только принадлежащий ему xray и сам переписывает секцию логов.
«Открывать при входе» использует стандартный объект входа (Системные настройки › Основные › Объекты входа).

## Как проверить

1. `scripts/audit.sh` — детерминированная опись: бюджет размера и каждое место, где есть
   запуск процессов, сеть, запись файлов, привилегии, динамическая загрузка кода или
   конструкции, похожие на обфускацию. Вывод должен совпадать с таблицей выше.
2. `docs/ru/AUDIT.md` — чек-лист проверки, который одновременно служит инструкцией для ИИ-модели.
3. Прочитайте `Sources/XrayBar/*.swift` по порядку номеров и скрипт сессии. Это всё приложение.
4. Понаблюдайте за работой: `sudo fs_usage -w -f filesys XrayBar`, `nettop -p XrayBar` и
   `ps -axo pid,user,command | grep xray` до и после отключения.

## Как сообщить о проблеме

Уязвимость: сообщите приватно через *Report a vulnerability* на вкладке
[Security](https://github.com/heaprip/xraybar/security/advisories/new) репозитория, не в issue.
Всё остальное: создайте issue.
