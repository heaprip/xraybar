# Безопасность и доверие

[English](../SECURITY.md) · **Русский**

XrayBar запрашивает пароль администратора и стоит на пути всего вашего трафика. Вам не
должно быть нужно доверять автору, чтобы им пользоваться. Этот документ описывает, что
делает приложение, от чего оно может и не может защитить и как проверить это самостоятельно.

## Модель доверия в одном абзаце

Не доверяйте бинарникам: собирайте из исходников (`swift build`, около 30 с, только Command
Line Tools). Не верьте автору на слово насчёт исходников: они достаточно малы, чтобы их
прочитать, а `scripts/audit.sh` и `docs/ru/AUDIT.md` позволяют проверить их вам самим или
ИИ-модели, которую запускаете вы. Не доверяйте загрузкам: Xray-core и файлы `.dat`
проверяются по контрольным суммам из upstream. Самому Xray-core доверие оказывается как
upstream-проекту XTLS; XrayBar его не изменяет.

## Что делает приложение

| Область | Поведение | Где |
|---|---|---|
| Root | Один запрос пароля на каждый Connect запускает `xraybar-session.sh`, и больше ничего | `Sources/XrayBar/Resources/xraybar-session.sh` |
| От root | копирует конфиг в `/var/run/xraybar`, запускает xray, меняет DNS, ждёт, останавливает xray, восстанавливает DNS; `--restore` убирает следы погибшей сессии | тот же скрипт |
| Сеть (приложение) | только по команде *Update Xray and Routing Data*: релиз Xray и выбранный источник `.dat` на GitHub; каждый файл до использования сверяется с SHA-256 из upstream; эфемерная сессия без cookies и кэша | `7-Assets.swift` |
| Запись файлов | `~/Library/Application Support/XrayBar/` (библиотека, сгенерированный конфиг, стоп-файл, `core/` со скачанными Xray и `.dat`); `/var/run/xraybar/` (root: копия конфига на время подключения, pid; `/var/db/xraybar/dns.saved` переживает перезагрузку; лог читают только администраторы; в нём только ошибки, пока не включён Detailed Log) | `2-Store.swift`, скрипт |
| Чтение файлов | перечисленное выше; по желанию база v2rayN для разового импорта (только чтение); буфер обмена и файлы картинок — только по команде Import (QR распознаётся на устройстве через Vision) | `3-Import.swift`, `6-Menu.swift` |
| Процессы | запрос пароля (`NSAppleScript`), `xray run -test` для проверки конфига; `ditto` для распаковки и `xray version` после загрузки | `5-Session.swift`, `7-Assets.swift` |
| Секреты | на этапе 1 профили хранятся в обычном JSON (права 600); Keychain запланирован | `2-Store.swift` |

Больше ничего: ни телеметрии, ни отчётов о сбоях, ни проверки обновлений, ни аналитики.

## Модель угроз

Защищает от:
- того, что приложение делает не то, что написано в исходниках (собирайте сами);
- скрытой сетевой активности приложения (сетевой ввод-вывод разрешён в одном месте, его легко найти grep);
- остаточного состояния: осиротевших root-процессов, оставшихся маршрутов, DNS, который
  продолжает указывать в туннель, в том числе после потери питания или гибели root-скрипта
  (при следующем запуске предлагается «Restore»);
- запуска под root конфига, который пишет произвольные файлы: скрипт работает с собственной
  копией конфига, принадлежащей root, и отклоняет конфиги с путями к лог-файлам.

Не защищает от (известные ограничения этапа 1):
- **Вредоноса, уже запущенного под вашим пользователем.** Он может подменить бинарь xray
  или скрипт в каталогах, доступных пользователю на запись, до того как вы введёте пароль.
  Это справедливо для любой схемы «спросить пароль и запустить утилиту из домашней папки»,
  включая v2rayN (который вдобавок передаёт пароль sudo через stdin). На этапе 3
  привилегированная часть переезжает в LaunchDaemon, принадлежащий root, и это закрывает дыру.
- Скомпрометированного релиза Xray-core в upstream. Контрольные суммы доказывают, что вы
  получили то, что опубликовал XTLS, но не то, что это безопасно. Xray можно собрать из
  исходников с помощью Go и сравнить.
- Анализа трафика и всего, что выходит за рамки свойств безопасности самого Xray.

## Как проверить

1. `scripts/audit.sh` — детерминированная опись: бюджет размера и каждое место, где есть
   запуск процессов, сеть, запись файлов, привилегии, динамическая загрузка кода или
   конструкции, похожие на обфускацию. Вывод должен совпадать с таблицей выше.
2. `docs/ru/AUDIT.md` — чек-лист проверки, который одновременно служит инструкцией для ИИ-модели.
3. Прочитайте `Sources/XrayBar/*.swift` по порядку номеров и скрипт сессии. Это всё приложение.
4. Понаблюдайте за работой: `sudo fs_usage -w -f filesys XrayBar`, `nettop -p XrayBar` и
   `ps -axo pid,user,command | grep xray` до и после Disconnect.

## Как сообщить о проблеме

Создайте issue, а если дело чувствительное, сначала свяжитесь с мейнтейнером лично.
